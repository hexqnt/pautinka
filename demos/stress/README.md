# Stress laboratory

Интерактивное демо производительности Pautinka для браузера (WASM + WebGL2) и настольной версии. При запуске граф из 100 вершин растёт через ступени 250, 500, 1 000, 2 500, 5 000, 10 000 и 20 000 вершин. Область роста имеет пропорции примерно 4:3 и заполняется от центра наружу; незавершённый внешний виток немного меняет соотношение сторон. Шаг сетки примерно 55,43×41,57 сохраняет площадь на вершину исходной сетки 48×48, а центры существующих орбит не меняются при добавлении вершин. По умолчанию на каждую вершину приходится три исходящих ребра; большинство связей локальные, часть дальние. Цепочка соседних вершин обеспечивает связность. Это генератор нагрузки, без физической симуляции и автоматической раскладки.

## Запуск в браузере

Из корня репозитория:

```sh
rustup target add wasm32-unknown-unknown
cd demos/stress
trunk serve --release
```

Откройте `http://localhost:8081`. Для измерений используйте release: отладочная сборка существенно меняет затраты геометрии и отрисовки. Демо не загружает данные по сети, не использует потоки, SharedArrayBuffer и специальные заголовки изоляции. Времена CPU измеряются через `web-time`, в браузере на базе Performance API. Возвращение на скрытую вкладку сбрасывает окно измерений; анимация и рост не догоняют время, проведённое в фоне. Шаг анимации ограничен 50 мс, чтобы длинный кадр не вызывал скачок координат; поэтому под высокой нагрузкой движение замедляется.

Настольный запуск:

```sh
cargo run --release -p pautinka-stress
```

## Управление

**Animate** приостанавливает движение, **Auto grow** независимо управляет ростом, **Restart** применяет seed и возвращает начальное число вершин (по умолчанию 100), сохраняя текущие настройки оформления и топологии. Продолжительность ступени настраивается от 3 до 30 секунд (по умолчанию 10); если конфиг задаёт другое значение, диапазон ползунка расширяется до него. На максимальном размере рост останавливается. Во время перетаскивания вершины таймер роста приостановлен. Ручной выбор числа вершин отключает автоматический рост; изменение плотности связей сохраняет его состояние. Положение оставшихся вершин и центры их орбит сохраняются при изменении нагрузки.

Каждая вершина движется по своей эллиптической орбите. Захваченная вершина следует за курсором, после отпускания продолжает движение около нового центра без скачка. Escape и отмена жеста возвращают исходное положение и центр орбиты. Перетаскивание фона перемещает камеру, колесо и щипок меняют масштаб. **Auto fit** включён по умолчанию и автоматически вписывает граф при росте и движении; на время перетаскивания вершины вписывание приостанавливается. Для свободного перемещения камеры и масштабирования отключите этот режим. Home, нажатие средней кнопки мыши на холсте и двойное нажатие по фону выполняют разовое вписывание. Для сравнения замеров учитывайте число элементов в области просмотра и используйте одинаковый ракурс.

Кнопки управления и меню расположены в одной строке с горизонтальной прокруткой на узком экране; содержимое меню прокручивается вертикально:

- **Load**: 100–20 000 вершин, соотношение E/V от 0 до 16 с шагом 0,01, длительность ступени и seed. Число рёбер равно округлённому `V × E/V`; дробная часть распределяется между вершинами равномерно. При E/V = 0 граф состоит из отдельных вершин. Меню также показывает среднюю степень без учёта направлений — `2E/V`.
- **Topology**: локальность, радиус окрестности, концентрация входящих связей на хабах, число хабов и связующий каркас. Пресеты **Local / Mixed / Random / Hubs** меняют эти параметры вместе; размер и E/V задаются независимо.
- **Motion**: доля движущихся вершин 0–100% и скорость 0–3×. Выключенные вершины сохраняют фазу и положение.
- **Nodes**: 1–12 цветов, размер, круги, прямоугольники, ромбы, треугольники, шестиугольники или смесь.
- **Edges**: прямые, кривые, ломаные 90°/45°/15°, радиус скругления их углов **Corner radius** (0 отключает скругление), сплошной/штриховой/точечный рисунок, стрелки и оформление пересечений. Разрывы и мостики доступны для всех режимов геометрии.
- **View**: подписи и порог их масштаба, мини-карта, сетка и обзорное упрощение (LOD). По умолчанию мини-карта, сетка и LOD включены, подписи и декорации пересечений выключены. LOD автоматически упрощает отрисовку при масштабе меньше 0,2 или числе видимых вершин и рёбер суммарно больше 20 000.

## Подбор сценария

| Параметр | Что изменяет | Для каких сценариев полезен |
|---|---|---|
| E/V | Число рёбер и среднюю степень | Разреженные графы, деревья по плотности, более насыщенные сети |
| Local links | Предпочтение пространственно близких связей | Схемы с короткими линиями или графы с большим числом длинных связей через область просмотра |
| Local radius | Окрестность в ячейках сетки по каждой оси | Плотные локальные связи или более протяжённые соседства |
| Hub links / Hub nodes | Долю связей, направленных в небольшой набор вершин | Зависимости с общими узлами, звёзды, проверку переноса вершины с большим числом инцидентных рёбер |
| Connected backbone | Цепочку, связывающую все вершины при E/V ≥ 1 | Связный документ или возможность получить отдельные компоненты |
| Moving nodes / Speed | Долю изменяющейся геометрии и скорость движения | Статичный граф, редкие обновления или непрерывное изменение всей сцены |

**Local links** и **Hub links** задают вероятностные предпочтения для связей вне каркаса. Сначала выбирается связь с хабом; для остальных применяется локальность. Локальная окрестность задаётся как ±радиус целочисленных ячеек по каждой оси, до анимации и ручного переноса. Хабы выбираются детерминированно по seed и размеру графа. Если выбранные соседи исчерпаны, генератор добирает глобальные связи: точное число рёбер сохраняется, петель и повторных пар источник–цель нет. Обратная связь между той же парой вершин допускается как отдельное ребро.

Каркас гарантирует связность при E/V ≥ 1 и занимает `V − 1` рёбер. При меньшей плотности он не применяется. Выключение каркаса разрешает отдельные компоненты, но не гарантирует их наличие в плотном случайном графе. Пресеты задают приближённые сценарии нагрузки, без воспроизведения конкретного семейства случайных графов или физической раскладки.

Например, для преимущественно коротких линий можно выбрать E/V = 2,5, Local links = 100%, Local radius = 2, Hub links = 0%. Для графа зависимостей с общими узлами — E/V = 3, Local links = 20%, Hub links = 70%, Hub nodes = 4, каркас выключен. Большое число длинных рёбер увеличивает число пересечений и рёбер, проходящих через видимую область, даже если самих видимых вершин немного.

## Метрики

Полупрозрачный HUD находится поверх холста в левом верхнем углу и пропускает нажатия, перетаскивание и прокрутку к графу. Он показывает FPS, средний интервал кадра, p50/p95/p99 и максимум, CPU-время модели и виджета, видимое/полное число вершин и рёбер, размер окна измерений, память индекса и время последнего построения. Нижней панели и графика нет.

Статистика обновляется четыре раза в секунду по последним 600 кадрам текущей нагрузки. Текст HUD форматируется с той же частотой в переиспользуемые строки. При изменении размера, топологии, оформления или движения окно сбрасывается. Процентили считаются методом ближайшего ранга; p99 появляется после 100 образцов. Видимые рёбра считаются по пересечению их bounding box с областью просмотра, а не по точному пересечению нарисованных сегментов. Счётчики видимости обновляются с той же частотой.

**FPS** вычисляется как обратное среднему интервалу между началами последовательных кадров egui. В браузере этот интервал включает ожидание vsync и задержки выполнения; это не отдельный таймер GPU. Кадр построения новой ступени входит в статистику этой ступени, поэтому стоимость роста не скрывается.

**CPU model** — среднее время применения настроек модели, построения графа, движения и обработки событий перетаскивания. **CPU widget** — среднее время `Canvas::show_with`, включая подготовку пространственного индекса и создание shapes. Эти таймеры исключают панели и HUD демо, сбор статистики, тесселяцию, отправку на GPU и ожидание показа кадра. **BUILD** — последнее построение модели; подготовка индекса относится к CPU widget. **INDEX** — `Canvas::stats().spatial_cache_bytes`, это не память всего WASM-процесса. Накопительные числа перестроений и обновлений индекса доступны в меню View.

Генератор, орбиты и порядок элементов детерминированы для seed, параметров топологии и последовательности шагов времени. Изменение топологии сохраняет позиции вершин и центры их орбит; при росте сохраняются все параметры. Пакет движения один раз пересчитывает каждое затронутое ребро и публикует полный журнал изменений. Буферы и цвета переиспользуются; прямые и кривые хранят геометрию inline. Ломаные используют штатный маршрутизатор и выделяют массив точек при перестроении — это часть нагрузки выбранного режима.

## Воспроизводимое CPU-профилирование

Для записи профиля обычного оконного демо на Linux запустите из корня репозитория:

```sh
./profile.sh
```

Нужны Rust toolchain и `perf`. Скрипт собирает нативное release-приложение с таблицами строк в отдельном каталоге, затем запускает его под `perf record` с раскруткой стека через DWARF. Настройки, движение и рост доступны как при обычном запуске. Закройте окно, чтобы завершить запись; путь профиля и команда `perf report` выводятся в терминал. По умолчанию каждая запись получает отдельный каталог внутри `target/stress-profile/`. Можно передать свой путь: `./profile.sh target/stress.perf.data`. Относительные пути считаются от текущего каталога; существующие файлы не перезаписываются. Доступ к аппаратным счётчикам должен быть разрешён настройками системы. Запись включает запуск приложения.

### Сценарии TOML

Для автоматического прогона передайте файл сценария. Готовые примеры: [рост до 5000 вершин](scenarios/growth.toml) и [фиксированная нагрузка на 30 секунд](scenarios/fixed.toml).

```sh
./profile.sh --config demos/stress/scenarios/growth.toml
./profile.sh --config demos/stress/scenarios/fixed.toml target/fixed.perf.data
```

Скрипт сохраняет копию сценария рядом с профилем как `<OUTPUT>.toml` и запускает приложение именно с этой копией. Для запуска без `perf` используется тот же конфиг:

```sh
cargo run --release -p pautinka-stress -- --config demos/stress/scenarios/growth.toml
```

Минимальный сценарий роста:

```toml
[run]
max_nodes = 7500
hold_secs = 15

[growth]
interval_secs = 5
```

Все поля необязательны; пропущенные настройки соответствуют обычному интерактивному запуску. Неизвестные поля, неподдерживаемые значения и противоречащие друг другу настройки приводят к ошибке до открытия окна. Автоматическая загрузка конфига из текущего каталога не выполняется. Браузерный запуск использует обычные настройки без чтения файла.

| Раздел | Поля и значения по умолчанию |
| --- | --- |
| Корень | `seed = 42` |
| `run` | `duration_secs` и `max_nodes` отсутствуют; `hold_secs = 10` при заданном `max_nodes` |
| `load` | `nodes = 100` (100–20 000), `edges_per_node = 3.0` (0–16) |
| `growth` | `enabled = true`, `interval_secs = 10` |
| `topology` | `locality = 85` (0–100), `local_radius = 3` (1–16), `hub_share = 0` (0–100), `hubs = 4` (1–32), `backbone = true` |
| `motion` | `animate = true`, `fraction = 100` (0–100), `speed = 1.0` (0–3) |
| `nodes` | `kind = "mixed"`, `colors = 6` (1–12), `radius = 7.0` (3–16) |
| `edges` | `routing = "curved"`, `direction = "undirected"`, `pattern = "solid"`, `corner_radius = 0.0`, `crossings = "none"` |
| `view` | `auto_fit = true`, `labels = false`, `lod = true`, `minimap = true`, `grid = true` |

`duration_secs` ограничивает реальное время от первого кадра демо, без сборки и начального создания сцены. `max_nodes` ограничивает рост и ручной выбор числа вершин; допустимы любые целые значения от начального размера до 20 000. Если цель лежит между стандартными ступенями, последняя ступень заканчивается точно на ней. После достижения цели приложение работает ещё `hold_secs` секунд и штатно закрывает окно, завершая запись `perf`. Если одновременно заданы время и цель, срабатывает первое условие завершения. Проверка выполняется на кадрах UI, поэтому длинный кадр может задержать закрытие.

Все длительности задаются в секундах, допускается дробная часть. Время прогона и интервал роста должны быть положительными, время удержания может быть нулевым. `hold_secs` требует `max_nodes`; цель выше начального размера требует включённого роста. Если цель равна начальному размеру, удержание начинается с первого кадра даже при выключенном росте. Без условий `run` демо работает до ручного закрытия. **Restart** сбрасывает оба таймера. Остановка анимации или роста не останавливает таймер прогона; уменьшение нагрузки ниже цели сбрасывает время удержания.

Значения `nodes.kind`: `mixed`, `circle`, `rectangle`, `diamond`, `triangle`, `hexagon`. Значения `edges.routing`: `curved`, `straight`, `orthogonal`, `octilinear`, `angular15`; `direction`: `undirected`, `forward`, `reverse`, `both`; `pattern`: `solid`, `dashed`, `dotted`; `crossings`: `none`, `gap`, `bridge`. `edges.corner_radius` — конечный неотрицательный радиус в координатах графа: 0 отключает скругление, для прямых и кривых значение не применяется. Декорации пересечений доступны для всех режимов геометрии, включая `curved`.

### Замеры без окна

Для воспроизводимого замера модели и UI без окна:

```sh
cargo run --release -p pautinka-profiling --example stress -- 1000 120
```

Позиционные аргументы — число вершин (100–20 000) и число измеряемых кадров. Параметры топологии можно повторить из интерфейса:

```sh
cargo run --release -p pautinka-profiling --example stress -- 1000 120 --ratio 2.5 --locality 20 --radius 3 --hub-share 70 --hubs 4 --no-backbone --seed 42
```

`--help` показывает все параметры. По умолчанию используются E/V = 3, Local links = 85%, Local radius = 3, Hub links = 0%, Hub nodes = 4, включённый каркас и seed 42. CSV сохраняет все эти значения вместе с количеством вершин и рёбер.

`--minimap` включает мини-карту для сравнения с обычным оконным сценарием. CSV содержит этот переключатель и количество shapes/вершин меша последнего измеренного кадра (`last_shapes`, `last_vertices`); при `--model-only` оба счётчика равны нулю.

Сценарий использует ту же модель `scene::Scene` и общий `CpuUiHarness` из `tools/test-support`: кривые, движение всех вершин, фиксированный шаг 1/60 с, viewport 1440×1000, начальное вписывание, пять прогревочных кадров, выключенные подписи, пересечения и LOD. CSV отдельно показывает модель (`model`), модель с UI (`model_and_ui`), тесселяцию и их сумму для каждого кадра. GPU и браузер в этом сценарии не участвуют. UI-взаимодействия проверяются через `egui_kittest` в `tools/tests/tests/stress_ui.rs`.

Для изоляции затрат модели добавьте `--model-only`: выполняются те же шаги анимации без вызовов UI и тесселяции, CSV содержит только фазу `model`.

```sh
cargo run --release -p pautinka-profiling --example stress -- 5000 500 --model-only
```

Модель собирает границы графа в тех же проходах, что и журнал изменённых вершин и перестроение рёбер. Расчёт `EdgePath` остаётся частью каждого шага: это вызовы геометрии библиотеки, а не накладные расходы измерителя.

## Структура

`scene/config.rs` задаёт типизированные параметры и общие диапазоны для модели и UI, `scene/generate.rs` — генератор, `scene/graph.rs` — заимствованное представление `Graph`, `scene.rs` — движение, перетаскивание и журнал геометрии. `app.rs` связывает модель с холстом; меню, таймер роста, renderer и панель статистики находятся в `app/`. `metrics.rs` хранит длительности как `Duration`, объединяет CPU-замеры повторных проходов egui и связывает их с интервалом следующего кадра. Производные формы и цвета кешируются в сцене отдельно от копируемых настроек.

## Статический хостинг

```sh
cd demos/stress
trunk build --release --public-url ./
```

Весь каталог `target/stress-dist/` готов для статического HTTPS-хостинга, включая размещение в подкаталоге. Сервер должен отдавать `.wasm` с MIME `application/wasm`. В HTML используется `wasm-opt -O2`: приоритет у скорости выполнения.

## Публикация

CI собирает release-WASM после проверок на push и pull request; артефакт `stress-demo` содержит готовый статический сайт. Push основной ветки загружает его в Yandex Object Storage, бакет `pautinka.hexq.ru`. Локальная сборка: `./build_and_push.sh --build-only` из корня репозитория, результат в `target/stress-dist`. Секреты, параметры бакета и команды загрузки описаны в [руководстве релиза](../../.github/RELEASING.md).
