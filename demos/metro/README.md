# Городские связи

Презентационное демо Pautinka: карты метро Петербурга и Москвы с переключателем города, поиск станций, выделение линий, выбор станций и кратчайший маршрут по времени. Граф и положение камеры принадлежат приложению; Pautinka обеспечивает отображение, навигацию и выбор, а собственный `Renderer` рисует станции и линии. Начальная геометрия и индекс поиска готовятся при загрузке; при перемещении станции обновляются связанные рёбра и журнал геометрии с переиспользованием временного буфера. Прямые и кривые хранят геометрию inline; полилинии выделяют собственный массив точек при перестроении.

Данные из `data/spb.json` встроены через `include_str!`: демо не запрашивает JSON по сети. Названия, координаты и длительности сохранены из исходника. Подписи привязаны к станциям через `Shift` (сторона) и `Dx`/`Dy` (дополнительный сдвиг в координатах карты): обычные подписи справа имеют одинаковый отступ, а в узлах пересадок сдвиги разводят соседние названия. Связи считаются двусторонними; `Dist` интерпретируется как минуты, включая переходы между линиями. Маршрут минимизирует сумму этих значений, без ожидания поезда. Это демонстрационные данные, не актуальная транспортная схема.

## Запуск

```sh
cargo run -p pautinka-demo
```

Для браузера нужны целевая платформа WASM и [Trunk](https://trunkrs.dev/). Команды выполняются из корня репозитория:

```sh
rustup target add wasm32-unknown-unknown
cargo install --locked trunk
cd demos/metro
trunk serve
```

Откройте `http://localhost:8080`. Нужны WebAssembly и WebGL2. Выбор города и поиск станции находятся в верхней панели на любом экране. На узком экране линии и маршрут доступны через кнопку «Станции». Перетаскивание перемещает схему; колесо и щипок меняют масштаб; Home или двойное нажатие по фону вписывают всю схему. На общем обзоре маленького экрана подписи появляются при приближении; выбранная станция подписана при любом масштабе. Для маршрута выберите станцию, нажмите «Отсюда», затем выберите другую и нажмите «Сюда».

## Язык интерфейса

Демо автоматически выбирает русский для локалей с основным языком `ru` (например, `ru-RU` или `ru_RU.UTF-8`), английский — для всех остальных, включая неизвестную локаль. В браузере используется первый предпочитаемый язык браузера, в настольной версии — локаль системы. Переключатель **EN / RU** справа в нижней панели меняет язык сразу, сохраняя город, поиск, маршрут, выделение и настройки отображения. Ручной выбор действует до закрытия демо; при следующем запуске язык определяется заново.

Переведены настройки, поиск, маршрут, подсказки, названия городов и линий. Названия станций сохраняются в исходном виде из встроенных карт; поиск использует эти названия на обоих языках интерфейса.

## Поиск станций

Поиск использует `nucleo-matcher`: можно вводить полное название, часть букв или несколько сокращённых слов, например «бгв» для «Беговая» и «нв пр» для «Невский проспект». Регистр не учитывается. Выпадающий список показывает до восьми лучших совпадений в порядке оценки matcher.

Выберите станцию мышью или стрелками вверх/вниз и Enter. Escape, щелчок вне списка или очистка запроса закрывают список. После выбора камера приближает станцию; открытую станцию можно назначить началом или концом маршрута. Одноимённые станции различаются номером линии в результатах поиска. Названия подготовлены в UTF-32 один раз при загрузке, matcher и буфер результатов переиспользуются; ранжирование выполняется при изменении запроса.

## Настройки отображения

Над схемой находятся четыре меню с общей структурой: краткое пояснение, основной режим и связанные параметры. Изменения сразу видны на карте; общие настройки сохраняются при смене города в текущем сеансе. На узких экранах меню переносятся на следующую строку, а длинные списки настроек прокручиваются.

- **Линии и подписи**: прямые, кривые и ломаные с углами 90°, 45° или 15°; показ названий станций и минимальный масштаб их появления. Выбранная станция подписана при любом масштабе.
- **Пересечения**: без оформления, разрыв или дуга-мостик; порядок наложения, размеры и сторона дуги. Дополнительные параметры и настройки выбранного ребра раскрываются отдельно. Оформление доступно для прямых, кривых и ломаных.
- **Навигация**: мини-карта, её положение в одном из четырёх углов, вписывание всей схемы и памятка по жестам.
- **Сетка**: показ линий или точек, базовый шаг, минимальный экранный интервал, размеры и цвета делений. Видимость сетки независима от привязки к ней, которая настраивается в нижней панели.

## Перетаскивание и привязка

Перетаскивание станций включено постоянно. В нижней панели находятся переключатель «Привязка» и меню «Режимы привязки». Перемещение фона по-прежнему сдвигает обзор, а перемещение станции меняет её положение вместе со связанными линиями. Для перемещения группы сначала выделите станции через Ctrl/Command + нажатие или Shift + выделение области. Escape отменяет текущий жест и возвращает всю группу на исходные позиции.

Переключатель «Привязка» включает направляющие. В меню «Режимы привязки» независимо выбираются горизонталь, вертикаль и обе диагонали под 45°. По умолчанию выбраны горизонталь и вертикаль. При выключенной привязке или пустом наборе направлений движение свободное. Направляющие появляются во время захвата; выбранные режимы сохраняются при выключении привязки.

Изменения координат действуют в текущем сеансе. Встроенный JSON не перезаписывается; перезапуск демо восстанавливает исходную схему. Связи и время маршрутов при перемещении сохраняются.

## Статический хостинг

```sh
cd demos/metro
trunk build --release --public-url ./
```

Содержимое `target/demo-dist/` готово для любого статического HTTPS-хостинга, в том числе GitHub Pages и размещения в подкаталоге. Загрузите весь каталог, включая JS и WASM, без переименования файлов. Сервер должен отдавать `.wasm` с MIME `application/wasm`. Бэкенд, внешние шрифты, ключи API и специальные заголовки изоляции не нужны. Первая сборка Trunk может скачать инструменты wasm-bindgen и wasm-opt.

Metro собирается локально командой выше. В CI проверяется его совместимость с WASM; автоматическая сборка статического сайта и публикация настроены только для stress-демо.

## Структура и профилирование

`src/app.rs` содержит управление приложением, `src/app/header.rs` — верхнюю панель с выбором города и поиском, а `src/app/explorer.rs` — панель линий и маршрута; `src/metro.rs` — модель графа и обновление геометрии, `src/metro/route.rs` — поиск маршрута; `src/metro/load.rs` — разбор JSON и подготовку графа; `src/render.rs` — оформление схемы. Карты размещаются в `data/` рядом с приложением. Встроены карты СПб и Москвы в JSON; типы города и линий находятся в `src/metro/city.rs` и `src/metro/line.rs`.

Модули `metro` и `render` доступны из библиотечной цели `pautinka-demo`, поэтому сценарии в `tools/profiling` могут использовать ту же модель, загрузчик и renderer без запуска окна. Измерения следует выполнять через существующий harness из `tools/test-support`; UI-тесты остаются в `tools/tests`. Для воспроизводимого baseline нужно фиксировать карту, размер viewport, начальную камеру и последовательность действий.

## Московская карта и формат данных

Переключатель в верхней панели меняет город; при этом сбрасываются поиск, выделение линии и станций, маршрут и камера. Поиск, маршруты и редактирование геометрии работают для обеих карт. По умолчанию открывается Петербург, в том числе для существующих сценариев профилирования.

Петербургская карта содержит 75 станций на шести линиях по сверке на 18 октября 2026 года, включая «Горный институт», «Путиловскую» и «Юго-Западную». Удалена вымышленная «Площадь Кати», исправлены названия станций и линии 4, добавлен прямой переход «Садовая» — «Спасская». Геометрия остаётся схемой, а не географическими координатами.

`data/stations-msk.json` и `data/sections-msk.json` основаны на предоставленных YAML: 249 записей станций и 98 участков, включая историю и планы. После конвертации исправлены подтверждённые ошибки названий и дат, добавлены периоды пассажирского закрытия `closures`. Даты записаны строками ISO 8601; зависимости от YAML в приложении и инструментах сборки карты нет. Исходные YAML в корне сохранены без изменений как предоставленные пользователем материалы.

`data/msk.json` — подготовленный граф в общем со СПб формате: 238 станций на 14 линиях, срез исходных данных на 1 апреля 2021 года (последнее открытие в исходнике). Это географическое представление с приблизительным масштабом долгот относительно широт, а не официальная схема. Будущие записи с датой 2038 и закрытые интервалы эксплуатации исключены. Принадлежность станции к линии определяется её интервалом, а не цветом или названием; одинаковые названия на разных линиях остаются отдельными вершинами. МЦК, МЦД и монорельса в предоставленных данных нет.

Исправлен интервал участка «Парк Победы» — «Деловой центр» Солнцевской линии: он снова действует с 12.12.2020. В тот же день заканчивается период общего движения к «Шелепихе» БКЛ. Станции без действующих участков исключены (в том числе две оставшиеся записи Каховской линии). Точка перегиба Арбатско-Покровской линии и ещё не открытая в этом срезе Суворовская пропускаются при соединении соседних станций. Генератор отвергает невозможные периоды и неизвестные станции переходов.

Пересадки перечислены явными парами ID в генераторе карты: все пары внутри узла автоматически не соединяются. Исправлены два лишних прямых перехода в центре, добавлены «Красногвардейская» — «Зябликово» и переходы восстановленного «Делового центра». В исходнике нет времени: условно используются 3 минуты на перегон и 4 минуты на переход, без ожидания поезда. Петербургские веса тоже демонстрационные; для нового перегона вместо «Площади Кати» условно заданы 3 минуты, а не проверенное время движения. Полученные маршруты служат демонстрацией алгоритма.

В обоих JSON необязательное поле `Access` разбирается в enum: `open` (по умолчанию) или `transit_only`. Второй вариант оставляет пути для проезда, но исключает станцию из начала, конца и пересадок маршрута; в UI маркер перечёркнут и кнопки назначения недоступны. Для Петербурга так отмечены «Фрунзенская» и «Парк Победы», для Москвы на дату среза — «Смоленская» Арбатско-Покровской и «Рижская» Калужско-Рижской линии. Основания и оставшиеся ограничения приведены в [DATA_AUDIT.md](DATA_AUDIT.md).

Пересобрать карту из JSON можно через Rust xtask из корня репозитория:

```sh
cargo xtask build-msk
```

Пока оставляем JSON: оба города используют один загрузчик Serde и строгий enum линий; файлы удобно проверять и преобразовывать внешними инструментами. RON позволил бы писать Rust-подобные enum, кортежи и комментарии, что полезно для вручную редактируемой конфигурации со сложными вариантами. Для этих табличных данных переход потребует смены загрузчика и инструментов без усиления инвариантов модели: их задают типы и разбор, а не синтаксис файла. К RON имеет смысл вернуться, если формат карты станет конфигурацией с большим числом вариантов геометрии и оформления.

## Оформление пересечений

Меню «Пересечения» позволяет выбрать «Без оформления», «Разрыв» или «Дуга-мостик», настроить ширину, автоматический размер по толщине линий, высоту и сторону дуги, порядок рёбер, минимальный угол и отступ от изгибов. Выбор «Без оформления» сохраняет остальные параметры. Для выбранного ребра доступны индивидуальный приоритет, своё оформление и сброс настроек. Общие параметры сохраняются при смене города; индивидуальные настройки сбрасываются вместе со схемой. Оформление поддерживает прямые, кривые и ломаные.
